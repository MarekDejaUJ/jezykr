Ćwiczenie 2.1. Potok, select(), filter() i arrange()

Cel: Zapiszesz ciąg operacji na danych jako czytelny potok i poznasz pomocników wyboru kolumn.

Polecenie: W jednym potoku wybierz kolumny, odfiltruj zgłoszenia telefoniczne dłuższe niż 60 minut i posortuj je malejąco. Następnie wypróbuj wybór kolumn według nazwy i typu oraz filtry z %in%, between() i is.na().

Pakiet dplyr (ładuje go skrypt startowy) udostępnia funkcje-czasowniki: każda przyjmuje ramkę jako pierwszy argument i zwraca nową ramkę. Operator potoku |> przekazuje wynik z lewej strony jako pierwszy argument funkcji po prawej: x |> f(y) oznacza f(x, y). Potok czyta się „weź dane, a następnie…”. W RStudio wstawisz go skrótem Ctrl+Shift+M (Cmd+Shift+M), jeśli w Tools → Global Options → Code zaznaczysz Use native pipe operator.

  select(id, kanal, dzial, czas_min) |>

Ćwiczenie 2.2. Nowe zmienne: mutate(), if_else(), case_when() i cut()

Cel: Utworzysz nowe zmienne z działań arytmetycznych, warunków i przedziałów liczbowych.

Polecenie: Dodaj do danych czas w godzinach, koszt minuty, pełne godziny i resztę minut, miesiąc, kwartał, znacznik długiej obsługi, kategorię czasu oraz opis oceny. Sprawdź nowe zmienne funkcją count().

mutate() dodaje nowe kolumny albo zastępuje istniejące, zachowując liczbę wierszy. Nowa kolumna może korzystać z kolumn utworzonych wcześniej w tym samym wywołaniu. Działania wykonują się na całych kolumnach naraz, tak jak na wektorach w ćwiczeniu 0.3.

Ćwiczenie 2.3. Grupowanie i podsumowania: group_by(), summarise(), count() i across()

Cel: Zamienisz dane jednostkowe w zestawienia według grup i odróżnisz podsumowanie od przekształcenia w grupach.

Polecenie: Dla każdego kanału policz liczbę zgłoszeń, braki czasu, średnią, medianę i odchylenie standardowe czasu oraz odsetek spraw rozwiązanych. Policz kombinacje kanału i działu, średnie kilku zmiennych naraz według grupy procedury oraz różnicę czasu każdego zgłoszenia od średniej jego kanału.

group_by() nie zmienia wyglądu danych, lecz zapisuje, według których kolumn mają działać kolejne funkcje. summarise() zwraca jeden wiersz na grupę, a mutate() w grupach zachowuje wszystkie wiersze i liczy wartości w obrębie grupy. Argument .groups = "drop" usuwa grupowanie po podsumowaniu, dzięki czemu kolejne operacje nie działają niespodziewanie w grupach.

zgloszenia_analiza |>
  group_by(kanal) |>
  summarise(
    n = n(),
    braki_czasu = sum(is.na(czas_min)),
    sredni_czas = mean(czas_min, na.rm = TRUE),
    mediana = median(czas_min, na.rm = TRUE),
    odch_std = sd(czas_min, na.rm = TRUE),
    proc_rozw = 100 * mean(rozwiazano == "Tak"),
    .groups = "drop"
  )

Cel: Zmienisz układ tabeli między postacią długą i szeroką, obsłużysz braki funkcjami tidyr i połączysz rejestr zgłoszeń ze słownikiem działów.

Ćwiczenie 2.5. Próby losowe i symulacja

Cel: Wylosujesz powtarzalne próby z danych i rozkładów oraz zobaczysz, jak zmienia się średnia z próby.

Polecenie: Po set.seed() wylosuj wartości funkcją sample(), pobierz próbę 24 zgłoszeń i próbę warstwową 10% z każdego kanału, wygeneruj dane z rozkładu normalnego i sprawdź na 500 próbach, jak bardzo średnia z próby różni się od średniej całego zbioru.

Zadanie 2.6. Funkcja z walidacją i debugowanie

Cel: Napiszesz funkcję, która sprawdza poprawność argumentów, oraz znajdziesz błąd w cudzej funkcji narzędziami debugowania.

Polecenie: Napisz funkcję opisz(x, cyfry = 1), która dla wektora liczbowego zwraca nazwany wektor: liczbę elementów, liczbę braków, średnią, medianę i odchylenie standardowe. Funkcja ma zatrzymać się z czytelnym komunikatem, gdy x nie jest liczbowy. Następnie znajdź i popraw błąd w funkcji srednia_bez_skrajnych().

Funkcja z walidacją najpierw sprawdza argumenty, a dopiero potem liczy. stop("komunikat") przerywa działanie z Twoim opisem błędu; stopifnot(warunek) jest krótszą wersją dla prostych warunków. W bloku z opcją error=TRUE błąd zostanie pokazany w PDF, a renderowanie będzie kontynuowane — tak pokażesz, że walidacja działa.

opisz <- function(x, cyfry = 1) {
  if (!is.numeric(x)) stop("Argument x musi być liczbowy.")
  wynik <- c(n = length(x), braki = sum(is.na(x)),
             srednia = mean(x, na.rm = TRUE))   # dopisz medianę i sd
  round(wynik, cyfry)
}

Poniższa funkcja ma usunąć czasy spoza przedziału i policzyć średnią. Dla surowych danych działa, ale dla zgloszenia_analiza zwraca NA.

srednia_bez_skrajnych <- function(x, dolny = 0, gorny = 120) {
  x <- x[x >= dolny & x <= gorny]
  mean(x)
}

Zadanie 2.7. Pętla i warunek: program kontroli jakości

Cel: Połączysz funkcję, warunek, pętlę i wynikową ramkę danych w mały program.

Polecenie: Napisz funkcję ocen_kolumne(x, prog_brakow = 1), która zwraca „sprawdź”, gdy odsetek braków przekracza próg, a „OK” w przeciwnym razie, i odrzuca próg spoza 0–100. Pętlą for oceń kolumny dzial, czas_min, ocena, koszt i rozwiazano, zapisując wynik w ramce z nazwą kolumny, procentem braków i oceną. Porównaj wynik z wersją bez pętli.

Pętla for (i in seq_along(kolumny)) wykonuje ciało dla każdej pozycji wektora. Wynik zapisuj w obiekcie przygotowanym przed pętlą, np. ramce z kolumnami wypełnionymi NA. Warunek if (...) ... else ... wybiera jedną z dwóch dróg dla pojedynczej wartości; dla całych wektorów używasz ifelse() lub if_else().

Konstrukcja Zapis Uwagi
pętla for (i in seq_along(x)) { ... } seq_along() jest bezpieczniejsze niż 1:length(x) dla pustego x

kilka warunków ||, && wersje „i/lub” dla pojedynczych wartości w if
