Ćwiczenie 6.1. GitHub Copilot CLI: instalacja i bezpieczne uruchomienie

Cel: Uruchomisz asystenta CLI w folderze kursowym i poznasz granice jego dostępu do plików.

Polecenie: Aktywuj Copilot Free na koncie GitHub, sprawdź lub zainstaluj CLI, uruchom je w terminalu projektu, zaloguj się i zakończ sesję. W szablonie zapisz system, wynik copilot version, sposób logowania i ewentualny problem.

  1. Zaloguj się na GitHub własnym kontem i włącz Copilot Free, jeżeli nie masz aktywnego planu.
  2. W RStudio lub Positronie otwórz kartę Terminal (nie konsolę R). Terminal startuje w folderze projektu; sprawdź to poleceniem pwd (macOS) albo Get-Location (Windows).
  3. Wpisz copilot version. Jeżeli system nie zna tego polecenia, zainstaluj CLI według instrukcji GitHub: w Windows w PowerShell 6 lub nowszym winget install GitHub.Copilot, na macOS brew install --cask copilot-cli, a na każdym systemie z Node.js 22 lub nowszym npm install -g @github/copilot.
  4. Uruchom copilot. CLI zapyta, czy ufasz plikom w bieżącym folderze: potwierdź tylko dla folderu projektu jezykr. Jeśli CLI poprosi o logowanie, wpisz /login i postępuj według instrukcji.
  5. Przed każdą zgodą przeczytaj, czy asystent chce odczytać plik, uruchomić polecenie, czy zmienić plik. W tym kursie nie pozwalaj na zmiany plików bez przeczytania propozycji. Zakończ sesję poleceniem /exit.

Ćwiczenie 6.2. Podsumowania statystyczne z bibliotek R

Cel: Wygenerujesz podsumowanie liczbowe na trzy sposoby i porównasz propozycję asystenta z własnym kodem.

Polecenie: Zapytaj CLI o kod liczący liczność, braki, średnią, medianę i odchylenie standardowe czasu według grupy. Porównaj jego propozycję z kodem poniżej, a następnie wygeneruj tabelę opisową funkcją report_sample().

Przykładowe polecenie w sesji CLI:

W pliku R Markdown pracuję z ramką zgloszenia_analiza. Podaj krótki kod R z dplyr liczący n, liczbę braków, średnią, medianę i sd dla czas_min według kolumny grupa. Nie zgaduj wyników i nie uruchamiaj kodu. Wyjaśnij, co robi na.rm = TRUE, i zaproponuj test poprawności sumy liczebności.
summary(zgloszenia_analiza[, c("czas_min", "koszt", "ocena")])
statystyki <- zgloszenia_analiza |>
  group_by(grupa) |>
  summarise(
    n = n(),
    braki = sum(is.na(czas_min)),
    srednia = mean(czas_min, na.rm = TRUE),
    mediana = median(czas_min, na.rm = TRUE),
    sd = sd(czas_min, na.rm = TRUE),
    .groups = "drop"
  )
statystyki
stopifnot(sum(statystyki$n) == nrow(zgloszenia_analiza))
report::report_sample(zgloszenia_analiza, by = "grupa",
                      select = c("czas_min", "koszt", "kanal"))
Funkcja Najważniejsze argumenty Wynik
summary(object) ramka lub wektor kwartyle, średnia i braki każdej kolumny
summarise() z across() kolumny i funkcje, np. across(c(czas_min, koszt), \(x) mean(x, na.rm = TRUE)) własne podsumowanie w grupach
report::report_sample(data, by, select) by — zmienna grupująca; select — opisywane zmienne; centrality = "median" gotowa tabela opisowa próby

Sprawdź i zmień. Czy propozycja CLI użyła na.rm = TRUE we wszystkich funkcjach? Czy n - braki odpowiada liczbie obserwacji użytych do średniej? Porównaj report_sample() z tabelą statystyki: tabela automatyczna podaje dla grupy B n = 119, choć średnią czasu liczy ze 117 wartości — czy gdziekolwiek o tym informuje? Dodaj centrality = "median" do report_sample().

Kryteria sukcesu: tabela ma dwa wiersze, n = 121 i 119, 2 braki w grupie B, średnie 36,4 i 32,9 minuty; kontrola stopifnot() przechodzi; w szablonie zaznaczasz, która część kodu pochodzi z CLI, i wyjaśniasz, dlaczego liczność grupy w report_sample() nie jest liczbą wartości użytych do średniej.

Ćwiczenie 6.3. Wielkość efektu i jej automatyczna interpretacja

Cel: Obliczysz standaryzowane wielkości efektu z przedziałami ufności, sprawdzisz jedną z nich ręcznie i porównasz automatyczne etykiety według różnych konwencji.

Polecenie: Oblicz d Cohena i g Hedgesa dla czasu w grupach A i B, sprawdź d ręcznie z połączonego odchylenia standardowego, a następnie zinterpretuj wynik funkcją interpret_cohens_d() według trzech konwencji. Oblicz V Craméra dla kanału i rozwiązania sprawy, iloraz szans dla grupy i rozwiązania oraz cząstkowe eta-kwadrat dla modelu z ćwiczenia 5.4.

Wielkość efektu opisuje, jak duża jest różnica lub jak silny jest związek, niezależnie od liczebności próby. d Cohena to różnica średnich podzielona przez połączone odchylenie standardowe: d = 0,26 oznacza, że średnie różnią się o około ćwierć odchylenia standardowego. g Hedgesa to d z poprawką dla małych prób. Automatyczne etykiety („mały”, „średni”, „duży”) wynikają z przyjętej konwencji, a nie z danych — dlatego zawsze podawaj nazwę konwencji i oceniaj efekt w kontekście (czy 3,5 minuty ma znaczenie dla instytucji?).

dane_czas <- filter(zgloszenia_analiza, !is.na(czas_min))
d <- effectsize::cohens_d(czas_min ~ grupa, data = dane_czas)
d
effectsize::hedges_g(czas_min ~ grupa, data = dane_czas)
a <- dane_czas$czas_min[dane_czas$grupa == "A"]
b <- dane_czas$czas_min[dane_czas$grupa == "B"]
sd_pooled <- sqrt(((length(a) - 1) * var(a) + (length(b) - 1) * var(b)) /
                  (length(a) + length(b) - 2))
(mean(a) - mean(b)) / sd_pooled                 # kontrola ręczna
effectsize::interpret_cohens_d(d$Cohens_d, rules = "cohen1988")
effectsize::interpret_cohens_d(d$Cohens_d, rules = "sawilowsky2009")
effectsize::interpret_cohens_d(d$Cohens_d, rules = "gignac2016")
effectsize::cramers_v(xtabs(~ kanal + rozwiazano, data = zgloszenia_analiza))
effectsize::oddsratio(xtabs(~ grupa + rozwiazano, data = zgloszenia_analiza))
model_lm <- lm(czas_min ~ kanal + grupa, data = zgloszenia_analiza)
effectsize::eta_squared(model_lm, partial = TRUE)
Funkcja Najważniejsze argumenty Wynik
cohens_d(formula, data, pooled_sd = TRUE) wynik ~ grupa; pooled_sd = FALSE — wersja bez połączonego SD; ci = 0.95 d z przedziałem ufności
hedges_g() jak wyżej d z poprawką dla małych prób
interpret_cohens_d(d, rules) rules = "cohen1988", "sawilowsky2009", "gignac2016" słowna etykieta według konwencji
cramers_v(x, adjust = TRUE) tabela; adjust — poprawka na obciążenie siła związku dwóch zmiennych kategorialnych
oddsratio(x) tabela 2 × 2 iloraz szans z przedziałem ufności
eta_squared(model, partial = TRUE) model lm() lub aov() część zmienności wyjaśniona przez każdy czynnik
interpret_r(), interpret_cramers_v(), interpret_eta_squared() wartość; rules etykiety dla innych miar

Zapytaj CLI: „Wyjaśnij znak i znaczenie d Cohena liczonego jako (średnia A − średnia B) / połączone SD. Czy z samej wielkości efektu wolno wnioskować o przyczynie? Nie podawaj etykiety mały/duży bez wskazania konwencji.” Porównaj odpowiedź z wynikiem kodu i z tym, że grupy przydzielono losowo.

Kryteria sukcesu: d Cohena wynosi 0,26 (95% CI 0,00–0,51) i zgadza się z obliczeniem ręcznym; wszystkie trzy konwencje dają etykietę „small”; skorygowane V Craméra wynosi 0,06, iloraz szans 2,57 (1,26–5,23), a cząstkowe eta-kwadrat 0,18 dla kanału i 0,04 dla grupy. Opis podaje konwencję i ocenia znaczenie praktyczne różnicy 3,5 minuty.

Ćwiczenie 6.4. Tekst wygenerowany przez pakiet report

Cel: Ocenisz automatycznie wygenerowany opis wyników statystycznych i przygotujesz własną, sprawdzoną wersję po polsku.

Polecenie: Wygeneruj opis testu t z ćwiczenia 5.2 i modelu z ćwiczenia 5.4 funkcją report(). Porównaj każdą liczbę z wynikami z poprzedniego spotkania, wskaż jedno sformułowanie wymagające korekty lub kontekstu i napisz własny akapit po polsku.

Pakiet report zamienia obiekt wyniku (test, model) w tekst w języku angielskim z liczbami i etykietami efektu. To przykład automatycznej interpretacji, która działa bez modelu językowego: tekst powstaje z reguł, dlatego jest powtarzalny, ale nie zna celu badania ani schematu zbierania danych.

test_t <- t.test(czas_min ~ grupa, data = dane_czas)
report::report(test_t, data = dane_czas)
report::report(model_lm)
model_glm <- glm(as.integer(rozwiazano == "Tak") ~ czas_min + grupa + typ_sprawy,
                 family = binomial(), data = zgloszenia_analiza)
parameters::model_parameters(model_glm, exponentiate = TRUE)
Funkcja Działanie
report(x, data) tekst opisujący test lub model; data — dane, z których liczono test
report_table(x) ten sam wynik jako tabela
parameters::model_parameters(model, exponentiate = TRUE) tabela współczynników modelu; exponentiate = TRUE zamienia je na ilorazy szans

Zwróć uwagę na etykiety „statistically significant” i „small” oraz na to, czego tekst nie mówi: że grupy przydzielono losowo, że wynik dotyczy danych fikcyjnych i że kategoria odniesienia kanału jest wybrana alfabetycznie. Jeżeli poprosisz CLI o tłumaczenie tekstu, sprawdź, czy nie zmieniło liczb ani nie dodało przyczynowości.

Kryteria sukcesu: liczby z report() zgadzają się z wynikami t.test() i summary(model_lm); wskazujesz co najmniej jedno sformułowanie wymagające kontekstu; własny akapit po polsku podaje różnicę w minutach, przedział ufności, p, wielkość efektu z konwencją i ograniczenie.

Ćwiczenie 6.5. Diagnoza błędu z pomocą CLI

Cel: Poprosisz asystenta o wyjaśnienie komunikatu błędu, zanim sam poprawisz kod.

Polecenie: Uruchom poniższy kod i skopiuj komunikat błędu. Poproś CLI o wyjaśnienie komunikatu bez modyfikowania plików, porównaj odpowiedź z podpowiedzią zawartą w komunikacie dplyr i popraw kod samodzielnie.

zgloszenia_analiza |>
  filter(kanal = "Telefon") |>
  count(grupa)

Przykładowe polecenie w CLI: „Wyjaśnij ten komunikat błędu R: [komunikat]. Nie zmieniaj żadnych plików. Wskaż przyczynę i poprawkę w jednym zdaniu.” Dobre komunikaty błędów, takie jak w dplyr, często same podpowiadają poprawkę; przeczytaj je, zanim zapytasz asystenta.

Kryteria sukcesu: w PDF widać komunikat błędu (blok z error=TRUE) i poprawiony kod, który zwraca 34 zgłoszenia telefoniczne w grupie A i 47 w grupie B; opis porównuje odpowiedź CLI z podpowiedzią z komunikatu.

Zadanie 6.6. Napraw kod i audytuj sugestię

Cel: Samodzielnie rozpoznasz błędy jawne i ukryte, użyjesz CLI do diagnozy i sprawdzisz poprawkę w R.

Polecenie: Poniższy kod ma liczyć średni czas i odsetek spraw rozwiązanych w kanale Online według grupy. Zawiera trzy błędy powodujące komunikat oraz dwa błędy, które nie dają komunikatu, ale zmieniają wynik. Poproś CLI o diagnozę bez modyfikowania plików, a potem napisz własną poprawioną wersję i sprawdź ją niezależnym obliczeniem.

zgloszenia_analiza |>
  filter(kanal = "Online") |>
  group_by(grupa) |>
  summarise(srednia = mean(czas_minn),
            odsetek = 100 * mean(rozwiazano == "tak")

Funkcje: filter(), group_by(), summarise(), mean(), n(); do niezależnej kontroli table() i prop.table() albo tapply(). W szablonie zapisz: listę znalezionych błędów, krótką diagnozę CLI, poprawiony kod z wynikiem i jedną sugestię asystenta, której nie przyjąłeś albo którą dodatkowo sprawdziłeś. Błąd ukryty jest groźniejszy od jawnego: kod działa, ale zwraca np. 0% rozwiązanych spraw. Jeżeli limit planu Free się wyczerpie, wykonaj diagnozę samodzielnie i opisz, jak ją sprawdziłeś.

Kryteria sukcesu: poprawiony kod zwraca średni czas 34,4 minuty i 70,2% rozwiązanych spraw w grupie A (n = 57) oraz 25,6 minuty i 87,2% w grupie B (n = 47); raport wymienia wszystkie pięć błędów i pokazuje niezależną kontrolę wyniku.

Zadanie 6.7. Mini-raport z dziennikiem użycia SI

Cel: Połączysz podsumowanie, wielkość efektu i interpretację w krótki raport dla decydenta i udokumentujesz użycie SI.

Polecenie: Napisz akapit (do 150 słów) dla kierownika obsługi: czy pilotażowa procedura B skraca czas obsługi i zwiększa odsetek spraw rozwiązanych przy pierwszym kontakcie. Liczby oblicz w bloku kodu: różnicę czasu z przedziałem ufności, d Cohena z etykietą według wskazanej konwencji, odsetki spraw rozwiązanych w obu grupach i iloraz szans z przedziałem. Dodaj jedno ograniczenie i tabelę dziennika użycia SI.

Zadanie 6.8. Szkic projektu grupowego
